# Give Graph Enrichment exclusive ownership of inferred graph facts

Status: Accepted (reset 2026-06-15 — exhaustive same-domain CEP-pair judgment; generalized 2026-06-16 — node + edge derivation; amended 2026-06-18 — densification removed and intrinsic difficulty adopted; amended 2026-06-19 — prerequisite hint label removed; amended 2026-06-22 — per-node batched judging; coverage unchanged, call grouping regrouped; amended 2026-06-23 — derived-layer semantic deduplication sub-stage)

## Decision

Graph Enrichment is the only operation that creates learner-neutral graph facts not asserted by a source. Each execution is an immutable **Enrichment Run** over one explicit published graph version and one enrichment configuration. It produces one **Derived Graph Layer** stored separately from the asserted graph.

Graph Enrichment derives **nodes as well as edges**. Beyond the published anchors it may **rescue** `source_mentioned` nodes (concepts a member Extraction Run mentioned verbatim but never defined, drawn from that run's rejected/optional admission proposals) and **mint** `llm_grounded` nodes for prerequisite concepts the source assumes but never teaches. Minted nodes carry `mintingReason: "assumed_prerequisite"` (the prior experiment-only `densification` reason was removed with F3 — see "no densification pass" below). Anchor-driven assumed-prerequisite minting remains bounded per-anchor and per-run. Minting is two stages — an inspectable proposal of node identity, then grounding generation — never local string construction. Every minted node carries a CEP-shaped generated grounding bundle, swappable in place by a later retrieval upgrade without changing node identity. No rescued or minted node ever enters the asserted graph; the asserted layer stays anchors-only with a verbatim evidence floor and zero asserted edges. The grounding-origin model and the non-verbatim trust contract for generated grounding live in ADR-0023.

**Rescue is durability-judged before a node is created (2026-06-16 refinement, U3).** After mention dedupe/merge, each aggregated rescue candidate passes a measured, cross-family **rescue durability judge** (`kg-independent-judge`) conditioned on the same-domain anchors it would scaffold: is it a durable prerequisite a learner must grasp before those anchors, or an incidental artifact (a method/system/ablation label, a pedagogical-role label, a source-local detail)? The judge is **drop-only** and **fails open with a flag** (KTD3, AGENTS rule 16): it removes a candidate only on a confident verdict whose grounding span is verbatim-present in the candidate's own mention evidence; on transport failure, invalid tool args, or an ungrounded verdict the node is **kept and flagged** `kept_judge_unavailable`, never silently vetoed. A dropped candidate's label stays reserved so minting cannot resurrect it. Every candidate's `accepted` / `dropped` / `kept_judge_unavailable` disposition is recorded on the Enrichment Run trace and persisted relationally. This is a measured neural gate, not a lexical deny-list of role or method names.

**The derived node set is semantically deduplicated before judging (2026-06-23 amendment, plan U1–U5).** After the derived node set is assembled (anchors ∪ rescued ∪ minted) and before per-node prerequisite judging, an opt-in **semantic-deduplication sub-stage** collapses same-domain near-duplicate nodes, so duplicate nodes never reach the judge and prerequisite chains form on the collapsed set. It strictly separates **propose** from **decide** (ADR-0012, AGENTS rule 20): embeddings (`kg-node-embedding`) propose within-domain near-duplicate candidate pairs by cosine with a recall-generous threshold and a bounded top-N per node — they never merge — and a separate **cross-family merge adjudicator** (`kg-independent-judge`) decides each proposed pair as `merge` or `keep_distinct`. Raw cosine never decides; a very-high-similarity pair is still routed to the adjudicator. Merged pairs are unioned (a transitive cluster collapses to one canonical); canonical selection is deterministic and recorded — an **anchor always wins** over an enrichment node, then more evidence, then lower stable id — so a merge only ever removes a derived enrichment node and **never mutates published Concept identity, IRIs, or the asserted version** (the published-identity boundary stays deterministic per ADR-0015; KTD1). A two-anchor cluster is refused outright. A merge keeps the canonical node, adds the absorbed surface labels as derived-layer aliases, threads the absorbed evidence into the canonical node's judge context, and records full propose+decide+canonical-selection provenance to `derived_node_merges` for Admin Lab inspection. The pass **fails closed**: an embedding failure skips that domain and an adjudicator failure degrades that pair to `keep_distinct`, both surfaced, never a silent merge (R13). It is opt-in — omitting either port leaves enrichment behavior identical (the exact-label baseline) — and changing it re-derives the layer via the enrichment config hash. The dedup decision is inherently judgment-based and is evaluated by real-use inspection, never a deterministic proxy (AGENTS rules 11/19); embeddings here only propose identity candidates and are never used to derive a prerequisite (ADR-0012).

Enrichment judges **every unordered same-domain relation exhaustively over the union of anchors and enrichment nodes**, feeding the prerequisite judge each node's evidence — an anchor's published Concept Evidence Profile, a rescued node's verbatim mention passages, or a minted node's generated grounding. Source-stated prerequisite prose reaches the judge as ordinary mention evidence; the former labeled prerequisite-hint assertion was measured redundant and removed (ADR-0016). **Coverage is unchanged from the original per-pair design; only the call grouping is regrouped (amended 2026-06-22, plan U5).** Each subject node, over the stable-id sort, is judged in one batched forced-tool call against its forward candidates (`j > i`), so the union of batched calls covers every unordered same-domain relation exactly once — `O(n)` calls instead of `O(n^2)` — and the application maps each candidate fail-closed (a direction naming neither concept, or a candidate the judge omits, degrades to `uncertain`, never an invented edge). A subject's candidate list is split by routing class — any candidate touching a generated node is ordered by a cross-family judge (ADR-0023), anchor-only candidates stay on the validated judge — and each class is chunked deterministically by a configurable per-batch cap so a large domain cannot grow one prompt unbounded. The same per-node call is the incremental-growth primitive: enriching one new node against an existing layer is this call with that node as subject. Batched calls use configurable bounded concurrency over subjects (default four) and preserve deterministic subject/candidate/result order; if any batched call exhausts the forced-tool retry budget the run fails without persisting a partial layer. An Enrichment Run records its model identities, per-candidate judgments, the per-node verbatim-floor dispositions, and deterministic edge dispositions (weak-edge cutting, cycle removal, transitive reduction). The relational Derived Graph Layer is the query surface; one immutable JSONB artifact retains the complete trace. Repeated executions with the same version and configuration remain distinct runs.

Graph Enrichment also scores every derived node with learner-neutral intrinsic difficulty. The difficulty method, its fused components, and its `EXPERIMENT_ONLY` trust are owned by ADR-0024; here the only enrichment-scope commitments are that every derived node is scored and that prerequisite edges remain the primary learner-path constraint while difficulty is a secondary signal.

Graph Enrichment never mutates the asserted graph and never reuses an asserted relation name; its only predicate is `inferred-prerequisite-of` (ADR-0016) — ordering is always an edge, never a node attribute. There is no densification/bridge-proposal pass: the removed F3 experiment is summarized as a completed outcome in `docs/plans/TODO.md`, not here. Any future cost-bound pair-selection mechanism is separate follow-up work and must be measured against exhaustive judgment before it can veto pairs.

## Context

Inferred prerequisite structure requires graph-global judgment and does not belong in a per-source Extraction Run or the deterministic asserted Graph-Version Build. With the core kept intentionally small, exhaustive same-domain pair judgment is the simplest correct behavior and removes the embedding-clustering blocking tier, whose hard-gating role was never earned. Separate Enrichment Runs keep publication provenance-pure while making inferred structure inspectable and independently replaceable by later methods.
