# design-sync notes — @lrnki/learner-app → claude.ai/design

Repo-specific gotchas for future syncs. Config lives in `config.json`; the conventions
header the design agent reads is `conventions.md`.

## What is synced, and why this shape

- The DS is `apps/learner-app` — the learner surface, whose `src/ui/index.ts` is an
  ESLint-enforced UI boundary and whose `src/ui/tokens.js` is the single semantic token
  authority. `apps/admin-lab` is deliberately NOT synced: it is stock shadcn on default
  tokens (ADR-0011 keeps it minimal), so it would teach the design agent nothing.
- Shape is `package`, but the app has no `dist/` and no `.d.ts` tree. Everything the
  converter needs is generated by `node .design-sync/prepare.mjs` (`cfg.buildCmd`) into
  gitignored locations — never into tracked source (repo rule 10), and never as a
  hand-maintained second copy of the export surface (repo rule 18):
  - `apps/learner-app/tmp/ds/ds-entry.tsx` — the DS entry. `export *` over `src/ui` plus
    every `src/components` module, so the export surface tracks source with no list to
    maintain. Also defines `DesignSystemProvider` (`cfg.provider`), mirroring the real
    root layout in `src/app/_layout.tsx`: SafeAreaProvider → QueryClientProvider → PortalHost.
  - `apps/learner-app/tmp/ds/styles.css` — `src/global.css` compiled through the repo's own
    pinned Tailwind v4. Output matches the app's Metro web export.
  - `apps/learner-app/dist/types/ds-props.d.ts` — see "Prop contracts" below.

## The two lib forks (both declared in `cfg.libOverrides`)

### `overrides/bundle.mjs` — React Native → web

esbuild cannot bundle this app as-is. Three Metro behaviours are reproduced in
`sharedBuildOptions` (so the runtime bundle and the export-evidence pass can never
resolve differently):

1. **`react-native-css`'s import rewrite.** NativeWind v5 styles on web through a runtime
   interop, not raw class pass-through: `nativewind/metro` installs a *resolver* that
   redirects `react-native` → `react-native-css/components`, whose wrappers turn
   `className` into react-native-web `$$css` style objects. `react-native-web`'s own
   `View` has no `className` handling at all. The same rewrite exists as a babel plugin
   at `react-native-css/dist/commonjs/babel/import-plugin.js` (what `nativewind/babel`
   re-exports), and that is what the fork runs — as a *plugin*, so it sees the specifiers
   before `babel-preset-expo` rewrites them to `react-native-web/dist/exports/*`.
   **Symptom if this breaks: everything renders, unstyled.** Check a rendered element's
   computed color — DS ink is `rgb(36, 31, 24)`; browser-default black means the rewrite
   is not firing.
2. **`babel-preset-expo` over app source only**, which owns the Reanimated 4 worklet
   transform exactly once (see `apps/learner-app/babel.config.js` — do NOT also add
   `nativewind/babel`, which would run the worklets plugin a second time).
3. **Metro's platform-extension resolution** via esbuild `resolveExtensions`
   (`.web.tsx` before `.tsx` — e.g. `src/ui/sheetBackdrop.web.tsx`), a `process` polyfill
   (`.design-sync/process-shim.js` — RN/Expo libs read it at module scope and throw before
   `window.LrnkiDS` is ever assigned), and `.js`/`.mjs` → `jsx` loaders because
   `@rn-primitives/*` publish untranspiled JSX.

react/react-dom stay externalized to `window.React` exactly as upstream. This is
load-bearing: it is what lets the claude.ai/design agent render these components with
*its* React. A Metro-built bundle would carry its own React copy and every hook would
throw "Invalid hook call".

### `overrides/source-kit.mjs` — DS pane groups

Only the `GROUPS` table plus three marked lines differ from upstream. Every component
lives in exactly `src/ui` or `src/components`, both on upstream's `GENERIC_DIR` list, so
all 60 would land in one "general" group. The other documented lever — a `cfg.docsMap`
stub with `category:` frontmatter — is **not** usable here: a doc body *replaces* the
synthesized `.prompt.md` (see `lib/emit.mjs`), which would cost every component its
source JSDoc, variant list, `## Examples` and `## Related`.

## Prop contracts (the non-obvious one)

These components declare props inline (`Readonly<{…}>` in the parameter list), not as a
named `<Name>Props` type, and an Expo app ships no `.d.ts` tree. The converter resolves
props by looking for `<Name>Props` in the package's `.d.ts` tree, so **every component
silently emitted `{ [key: string]: unknown }` while validate stayed green.** A green
validate is not evidence of a good contract — always spot-check an emitted `.d.ts`.

`prepare.mjs` fixes this by generating `dist/types/ds-props.d.ts`, one
`export type <Name>Props = ComponentProps<Entry["<Name>"]>` per component, letting the
TypeScript checker resolve the real structural shape. `dist/types` is a `findTypesRoot`
candidate that is both gitignored and excluded by the app's tsconfig, so it never enters
`pnpm typecheck`. Note `expo export` clears `dist/` — re-run `prepare.mjs` after one.

## Fonts

- `IMFellEnglish_400Regular` is loaded by expo-font at runtime in the app; designs need a
  static `@font-face`, so the OFL-licensed TTF is committed at `.design-sync/fonts/`
  (with `LICENSE_FONT`) and wired via `cfg.extraFonts`. The family name must stay exactly
  the key expo-font registers — `src/ui/foundation.tsx` sets it by `fontFamily` for the
  `map-title` variant.
- `cfg.runtimeFontPrefixes: ["System"]` suppresses a `[FONT_MISSING] "SystemAndroid"`
  warning. That value comes from `nativewind/theme`'s platform-scoped `--font-sans` and
  never applies on web — verified identical in the app's own Metro web export. It is not
  a brand face and there is nothing to ship.

## Environment

- Playwright browsers on macOS live in `~/Library/Caches/ms-playwright`, **not**
  `~/.cache/ms-playwright`. Cached build is `chromium-1223`, which is exactly what the
  repo's pinned `@playwright/test` 1.60.0 wants — the render check runs unmodified.
- Fresh clone: `npm i esbuild ts-morph @types/react` inside `.ds-sync/`, then
  `ln -sfn ../.ds-sync/node_modules .design-sync/node_modules` (the forks import `esbuild`
  and `ts-morph` bare; the link is gitignored, the forks that need it are not).

## Preview authoring

- **Fixtures come from the repo, not from literals.** `prepare.mjs` re-exports the app's own
  `sessionFixture` and `@lrnki/application`'s `buildTrailView` from the DS entry as
  `__previewSessionFixture` / `__previewBuildTrailView` (underscore-prefixed so they are not
  PascalCase components and read as scaffolding). Map and formation previews compose
  `__previewBuildTrailView(__previewSessionFixture())` — the exact pair every component test
  uses — so they cannot drift from the view model. The fixture is a single-concept expedition,
  so counts read "1 leg, 1 crystal"; where a component needs more, previews spread that real
  shape into extra rows rather than inventing a new one.
- **Previews are compiled WITHOUT the RN pipeline** (the DS is externalized to
  `window.LrnkiDS`), so a preview may only use DS exports plus plain elements. Importing
  `react-native` in a preview would not go through the className rewrite.
- Layout glue in previews uses inline `style`, not utility classes: Tailwind only emits
  utilities it saw in the app source, so an arbitrary class in a preview may not exist.
  `flex-col` in particular does NOT ship — RN surfaces are already column.
- **`MapParchment` takes a `seed`, not children** — it is a seeded background texture, not a
  container. Use `className="bg-map-parchment"` on a plain element for a map ground.
- Component-specific traps found while grading: `OverlayHeader`'s `frontier` icon tone is an
  OUTLINE on `bg-card`, so an `on-accent` glyph is invisible there (use `ink`; only `solid`
  takes `on-accent`). `Button`'s `busy` hides the label but keeps its footprint.
  `ExplorableTheoryText` matches EXACT slices, so a sentence-initial "Magma viscosity" will
  not match the term "magma viscosity".

## Known render warns (triaged — a warn NOT in this list is new)

- `SectionOverview` renders only its collapsed disclosure trigger. The leg list opens on tap
  and cannot render statically; the cards show the trigger with the current-leg indicator.
- `MatchingBoard` shuffles its clue/match tiles per mount, so its screenshot differs on every
  capture. Grades follow sources, not pixels, so this does not clear grades — but do not read
  a changed sheet as a regression. `disabled` has no visual treatment on this component.
- `CrystalSpecimen`'s `open` / `next` / `collected` materials differ only by gloss and facet
  contrast (`fogged` is the only hue change). The preview renders at 140px so the axis reads.
- `CrystalVista` is the one scoped component left on the floor card: it needs an open
  full-screen vista with focus state and async Guardian handlers, and the single-concept
  fixture would render a near-empty formation. Author it on a re-sync if a richer fixture exists.

## Re-syncing

```sh
node .design-sync/prepare.mjs                     # cfg.buildCmd — regenerates entry, types, CSS
# fetch the project's _ds_sync.json → .design-sync/.cache/remote-sync.json first, then:
node .ds-sync/resync.mjs --config .design-sync/config.json \
  --node-modules "$PWD/node_modules" --out ./ds-bundle --remote .design-sync/.cache/remote-sync.json
```

Re-copy the staged scripts first (`cp -r <skill>/…  .ds-sync/`) — a stale `.ds-sync/` runs an old
converter against current instructions. The project id lives in `config.json`; that file is the
only place it is recorded.

## Re-sync risks

- **The forks are the fragile part.** Diff `overrides/bundle.mjs` and
  `overrides/source-kit.mjs` against the bundled `lib/` copies on every re-sync; both are
  near-verbatim, so upstream changes should merge cleanly. `bundle.mjs`'s only real
  divergence is `sharedBuildOptions`; `source-kit.mjs`'s is the `GROUPS` table.
- **NativeWind v5 is a preview release** (`5.0.0-preview.4`, with a `lightningcss` override
  pinned in `pnpm-workspace.yaml`). If it changes how `className` reaches the element, the
  import-plugin path is the first thing to re-verify — and the failure is silent-unstyled,
  not an error.
- The `GROUPS` table names components explicitly; a component added to `src/components`
  will build and ship correctly but fall back to the `general` group until it is listed.
- `prepare.mjs` derives the export surface by regex over `export function|const` and by
  reading `src/ui/index.ts`'s export list. A component exported some other way (e.g.
  `export default`) will be missing from `srcmap.json` and from `cfg.componentSrcMap`.
